# QEDSpec Clause Guide

This document is the definitive reference for generating correct QEDSpec
clauses. Read this before writing any `.qedspec` output. Every clause must
use the correct `clause_type` or it will fail `qedgen check`.

---

## The Five Clause Types

### `guard`

**Timing:** pre-execution, evaluated before the instruction body runs

**Semantics:** a condition on account properties that must hold before the
instruction is allowed to execute. If the guard fails, the transaction
is rejected.

**Use for:**
- Signer requirements: `signer(authority)`
- Account ownership: `owner(vault, token_program)`
- Key equality between accounts: `authority.key == pool.authority`
- Account discriminator checks: `discriminator(pool, Pool)`

**Do NOT use for:**
- Value preconditions (use `requires`)
- Postconditions (use `ensures`)

**Examples:**
```
guard signer(authority)
guard owner(token_vault, spl_token_program)
guard authority.key == pool_state.authority
guard !pool_state.is_frozen
```

---

### `requires`

**Timing:** pre-execution, evaluated before the instruction body runs

**Semantics:** a condition on input values (instruction arguments or
derivable values) that must hold before execution. Distinct from `guard`
which is about account properties.

**Use for:**
- Non-zero amount checks: `amount > 0`
- Bounded parameter checks: `new_fee <= MAX_FEE`
- Range validations: `slippage_bps < 10000`
- Ratio validations: `collateral_ratio >= MIN_RATIO`

**Examples:**
```
requires amount > 0
requires new_fee_rate <= 1000
requires collateral_amount >= min_collateral(debt_amount)
```

---

### `ensures`

**Timing:** post-execution, evaluated after the instruction body completes

**Semantics:** a condition on state that must hold after the instruction
executes successfully. Used to specify the expected effect of the instruction.

**Use for:**
- Balance changes: `vault.balance == old_vault.balance - amount`
- State transitions: `position.status == PositionStatus::Closed`
- Output amount bounds: `swap_output <= reserve_out`
- Invariant preservation: the state after must satisfy certain properties

**Examples:**
```
ensures vault_balance == old_vault_balance - withdraw_amount
ensures position.status == PositionStatus::Active
ensures swap_output <= ctx.accounts.token_vault_out.amount
ensures fee_recipient.balance == old_fee_recipient.balance + fee_amount
```

---

### `invariant`

**Timing:** throughout execution, must hold before AND after

**Semantics:** a property that must be preserved by the instruction — it
holds before the instruction and must still hold after. Used for protocol
invariants that no instruction should violate.

**Use for:**
- Pool constant product: `reserve_a * reserve_b >= k`
- Solvency: `total_deposits >= total_borrows`
- Supply conservation: `total_supply == sum_of_balances`
- Protocol health conditions

**Examples:**
```
invariant pool.reserve_a * pool.reserve_b >= pool.k
invariant lending_pool.total_deposits >= lending_pool.total_borrowed
invariant token.total_supply == sum(token_accounts.amount)
```

---

### `establishes`

**Timing:** post-execution, for initialisation instructions only

**Semantics:** a property that this instruction creates for the first time.
Used exclusively in initialisation handlers. The property does not need to
hold before the instruction (the account may not exist) but must hold after.

**Use for:**
- Initial authority assignment: `pool.authority == authority.key`
- Initial state: `position.status == PositionStatus::Active`
- Initial configuration: `config.fee_rate == initial_fee_rate`

**Examples:**
```
establishes pool.authority == authority.key
establishes position.owner == depositor.key
establishes pool.status == PoolStatus::Active
establishes vault.bump == canonical_bump
```

## Common Mistakes

**Wrong:** Using `ensures` for a signer check.
```
// WRONG
ensures signer(authority)
```
Signer checks are preconditions. Use `guard`:
```
// CORRECT
guard signer(authority)
```

**Wrong:** Using `guard` for a postcondition.
```
// WRONG
guard vault.balance == old_balance - amount
```
Balance postconditions use `ensures`:
```
// CORRECT
ensures vault.balance == old_vault_balance - amount
```

**Wrong:** Using `establishes` in a non-init handler.
```
// WRONG (in a swap handler)
establishes swap_count == old_swap_count + 1
```
State changes in non-init handlers use `ensures`:
```
// CORRECT
ensures swap_count == old_swap_count + 1
```

**Wrong:** Using `invariant` for a one-time property.
```
// WRONG
invariant pool.authority == authority.key
```
Authority binding established at init uses `establishes`:
```
// CORRECT (in init handler)
establishes pool.authority == authority.key
```

## QEDSpec File Format

```
// Generated by Lemma — review before using with qedgen check
spec MyProgram
program_id "PROGRAM_ID_HERE"

handler initialize : State.Uninitialised -> State.Active {
  guard signer(authority)
  requires initial_fee <= 1000
  establishes pool.authority == authority.key
  establishes pool.fee_rate == initial_fee
  establishes pool.status == PoolStatus::Active
}

handler swap : State.Active -> State.Active {
  guard signer(user)
  guard owner(token_vault_in, spl_token_program)
  guard owner(token_vault_out, spl_token_program)
  requires amount_in > 0
  ensures swap_output <= vault_balance(token_vault_out)
  invariant pool.reserve_a * pool.reserve_b >= pool.k
}

handler withdraw : State.Active -> State.Active {
  guard signer(depositor)
  guard depositor.key == position.owner
  requires withdraw_amount <= position.deposited_amount
  ensures vault.balance == old_vault_balance - withdraw_amount
  ensures position.deposited_amount == old_deposited - withdraw_amount
}
```
